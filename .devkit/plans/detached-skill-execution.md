# Detached/Headless Skill Execution for devkit CLI

## Status: DRAFT

**Type:** CLI Enhancement
**Archetype:** N/A (infrastructure, not a skill)
**Complexity:** Medium
**Estimated Time:** 10-14 hours

## Summary

Add background/detached execution to the devkit CLI so that `devkit architect ~/projects/my-app "add feature"` can return immediately with a run ID, while the Claude Code session runs in the background. Users retrieve status and results via `devkit jobs`, `devkit result <run-id>`, and `devkit logs <run-id>`.

**Core insight:** The current `cmd_run_skill()` calls `subprocess.run()` synchronously — it blocks until Claude Code finishes. Detached execution replaces this with a watcher process that spawns Claude as its child, captures output to a run-specific directory, and finalizes metadata on completion. The devkit parent returns immediately after spawning the watcher. The existing state/registry model already tracks `last_invocation` — we extend it with a `runs/` directory for output capture and a process-liveness check.

## Context Alignment

### CLAUDE.md Patterns Followed

- **Python stdlib only:** No external dependencies. Uses `subprocess.Popen`, `os`, `signal`, `pathlib`, `json` — all stdlib.
- **Atomic writes:** Run metadata written atomically from the parent process via `_atomic_write_json()`. Watcher updates use inline atomic writes (`tempfile` + `os.rename`) since the watcher is a standalone snippet without access to `_atomic_write_json()`.
- **Validation tuples:** `(bool, error_msg)` pattern for all validation (including new `_validate_run_id()`).
- **Script placement:** All changes in `scripts/devkit_cli.py` — no new files outside the existing structure.
- **State model:** Extends the existing `.devkit/state.json` and `~/.claude-devkit/registry.json` patterns.
- **Test pattern:** New tests follow the `test-integration.sh` `run_test()` harness pattern.
- **Injection resistance:** Watcher receives all variable values via `sys.argv` (not f-string interpolation into source code), consistent with the project's posture against injection vectors.

### Prior Plans This Builds Upon

- **mvp-meta-harness.md** — Established the `devkit_cli.py` architecture, `cmd_run_skill()`, state/registry model, and validation patterns. This plan extends `cmd_run_skill()` with a `--detach` flag rather than rebuilding.

### Deviations From Established Patterns

1. **New `~/.claude-devkit/runs/` directory.** Run output needs a persistent location outside target projects (aligns with the future direction of "devkit puts nothing in project directories"). Each run gets `~/.claude-devkit/runs/<run-id>/` containing `meta.json`, `stdout.log`, `stderr.log`, and `result.json`.

## Goals

1. **Detached execution:** `devkit <skill> <target> [args] --detach` spawns Claude Code in the background, prints a run ID, and returns immediately.
2. **Status retrieval:** `devkit jobs` lists all running/completed/failed runs. `devkit jobs <target>` filters to one project.
3. **Result retrieval:** `devkit result <run-id>` prints the captured result (Claude Code JSON output). `devkit logs <run-id>` streams stderr (progress/warnings).
4. **Process lifecycle:** Detect whether a background run is still alive (PID check). Clean up stale runs.

## Non-Goals

- **Job queuing/scheduling.** No cron, no priority queue, no concurrency limits. Each `--detach` spawns one process. If the user runs 10 concurrent skills, they get 10 processes.
- **Remote execution.** Background runs are local processes on the user's machine.
- **Notification/callback.** No webhook, no desktop notification when a run finishes. The user polls with `devkit jobs`.
- **Run resumption.** If a detached run is killed, it's gone. No checkpoint/restart.
- **Persistent daemon.** No long-running devkit daemon process. Each `--detach` is a fire-and-forget `Popen`.

## Assumptions

1. `claude --print` produces JSON output on stdout and progress on stderr (confirmed by existing `_print_run_result()`).
2. The `~/.claude-devkit/` directory exists (created by `devkit init` or `install.sh`).
3. Python 3.8+ is available (same as existing requirement).
4. PID files are sufficient for liveness detection on macOS/Linux (no Windows support needed).

## Proposed Design

### Run ID Format

Reuse the existing audit logging convention: `YYYYMMDD-HHMMSS-<6-char-random>` (e.g., `20260821-143052-a1b2c3`). Generated by the same pattern used in `/ship` and `/architect`.

### Run Directory Structure

```
~/.claude-devkit/
├── registry.json          # Existing
└── runs/
    └── 20260821-143052-a1b2c3/
        ├── meta.json      # Run metadata (skill, target, args, pid, status, timestamps)
        ├── stdout.log      # Captured stdout from claude --print
        ├── stderr.log      # Captured stderr (progress, warnings)
        └── result.json     # Parsed result (extracted from stdout JSON envelope on completion)
```

### meta.json Schema

```json
{
  "schema_version": "1.0.0",
  "run_id": "20260821-143052-a1b2c3",
  "skill": "architect",
  "target": "/Users/imurphy/projects/my-app",
  "project_name": "my-app",
  "args": "add user authentication",
  "pid": 12345,
  "status": "running",
  "started_at": "2026-08-21T14:30:52Z",
  "completed_at": null,
  "exit_code": null,
  "devkit_version": "0.2.0"
}
```

Status transitions: `running` -> `completed` | `failed` | `stale` (PID no longer alive, no completion recorded).

### Process Architecture

The watcher process spawns Claude as its child. This ensures `os.waitpid()` works correctly (only succeeds for direct child processes on POSIX). The process tree at spawn time:

```
devkit CLI (parent)
  └── Watcher process (detached child, start_new_session=True)
        └── Claude process (child of watcher -- watcher can waitpid)
```

The devkit CLI writes initial `meta.json` (pid: None, status: running), spawns the watcher, then exits immediately. The watcher spawns Claude, updates `meta.json` with Claude's PID, calls `os.waitpid()` to block until Claude exits, then finalizes metadata and result files.

### Change 1: `--detach` Flag Extraction in `main()`

`--detach` must be extracted from `skill_args` **before** `split_skill_args()` and `validate_args()` run, because `validate_args()` rejects any argument starting with `--`. The extraction is a simple scan-and-remove:

```python
# In main(), after constructing skill_args from rest[1:]:
skill_args = rest[1:]

# Extract --detach before the split/validate pipeline
detach = "--detach" in skill_args
if detach:
    skill_args = [a for a in skill_args if a != "--detach"]

pre_sep_args, post_sep_args = split_skill_args(skill_args)
# validate_args(pre_sep_args) now never sees --detach
```

This handles all positional variants:
- `devkit architect ~/foo "feature" --detach`
- `devkit architect ~/foo --detach "feature"`
- `devkit architect ~/foo --detach -- --fast`

### Change 2: `_spawn_detached()` and `_spawn_watcher()`

```python
def _spawn_detached(skill, resolved, args_str, config, run_id):
    """Spawn a detached Claude Code session with output capture."""
    runs_dir = Path.home() / ".claude-devkit" / "runs" / run_id
    os.makedirs(runs_dir, mode=0o700)

    meta = {
        "schema_version": "1.0.0",
        "run_id": run_id,
        "skill": skill,
        "target": str(resolved),
        "project_name": resolved.name,
        "args": args_str[:1024],
        "pid": None,
        "status": "running",
        "started_at": utc_now_iso(),
        "completed_at": None,
        "exit_code": None,
        "devkit_version": VERSION,
    }
    _atomic_write_json(runs_dir / "meta.json", meta)
    os.chmod(runs_dir / "meta.json", 0o600)

    claude_cmd = config.get("claude_command", FALLBACK_DEFAULTS["claude_command"])
    print_flag = config.get("claude_print_flag", FALLBACK_DEFAULTS["claude_print_flag"])
    prompt = f"/{skill}" + (f" {args_str}" if args_str else "")
    invocation = [claude_cmd, print_flag, "--output-format", "json", prompt]

    env = os.environ.copy()
    env["CLAUDE_DEVKIT"] = str(get_devkit_root())

    # Spawn watcher -- the watcher itself spawns Claude as its child,
    # so it can use os.waitpid() to obtain the real exit code.
    _spawn_watcher(runs_dir, invocation, str(resolved), env)

    return run_id


def _spawn_watcher(runs_dir, invocation, cwd, env):
    """Spawn a background watcher that launches Claude and finalizes on completion.

    The watcher receives all variable values via sys.argv -- no f-string
    interpolation into source code. This prevents injection if path values
    ever contain Python string metacharacters.
    """
    watcher_script = '''
import os, json, sys, time, subprocess
from pathlib import Path
from datetime import datetime, timezone

run_dir = Path(sys.argv[1])
invocation = json.loads(sys.argv[2])
cwd = sys.argv[3]
meta_path = run_dir / "meta.json"

def atomic_write_json(path, data):
    """Inline atomic write (tempfile + rename). The watcher cannot import
    _atomic_write_json() from devkit_cli since it runs as a standalone snippet."""
    tmp_path = path.with_suffix(".tmp")
    fd = os.open(str(tmp_path), os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
    with os.fdopen(fd, "w") as f:
        json.dump(data, f, indent=2)
    os.rename(str(tmp_path), str(path))

# Open log files with restricted permissions (0o600)
stdout_fd = os.open(str(run_dir / "stdout.log"), os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
stderr_fd = os.open(str(run_dir / "stderr.log"), os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
stdout_log = os.fdopen(stdout_fd, "w")
stderr_log = os.fdopen(stderr_fd, "w")

# Spawn Claude as our child -- os.waitpid() works because we are its parent
proc = subprocess.Popen(
    invocation, cwd=cwd, env=os.environ.copy(),
    stdout=stdout_log, stderr=stderr_log,
)
stdout_log.close()
stderr_log.close()

# Update meta.json with Claude PID (atomic)
with open(meta_path) as f:
    meta = json.load(f)
meta["pid"] = proc.pid
atomic_write_json(meta_path, meta)

# Wait for Claude -- we ARE its parent, so waitpid succeeds
try:
    _, status = os.waitpid(proc.pid, 0)
    exit_code = os.WEXITSTATUS(status) if os.WIFEXITED(status) else -1
except ChildProcessError:
    exit_code = -1

# Parse result from stdout
try:
    stdout_data = (run_dir / "stdout.log").read_text()
    data = json.loads(stdout_data)
    result_path = run_dir / "result.json"
    result_fd = os.open(str(result_path), os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
    with os.fdopen(result_fd, "w") as f:
        json.dump(data, f, indent=2)
except Exception:
    pass

# Finalize meta.json (atomic)
meta["completed_at"] = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
meta["exit_code"] = exit_code
meta["status"] = "completed" if exit_code == 0 else "failed"
atomic_write_json(meta_path, meta)
'''
    subprocess.Popen(
        [sys.executable, "-c", watcher_script,
         str(runs_dir), json.dumps(invocation), cwd],
        start_new_session=True,
        stdout=subprocess.DEVNULL,
        stderr=subprocess.DEVNULL,
        env=env,
    )
```

### Change 3: Run ID Validation Helper

Centralized validation for run IDs used by `cmd_result()`, `cmd_logs()`, and `cmd_clean()`. Blocks path traversal (e.g., `../../../etc`).

```python
def _validate_run_id(run_id):
    """Validate run ID contains no path separators or traversal."""
    if Path(run_id).name != run_id:
        return False, f"Invalid run ID (path traversal rejected): {run_id}"
    return True, ""
```

### Change 4: `_status_color()` Helper

```python
def _status_color(status):
    """Return status string with ANSI color for terminal display."""
    colors = {
        "running": "\033[33m",   # yellow
        "completed": "\033[32m", # green
        "failed": "\033[31m",    # red
        "stale": "\033[90m",     # gray
    }
    reset = "\033[0m"
    color = colors.get(status, "")
    return f"{color}{status}{reset}" if color else status
```

### Change 5: `devkit jobs` Command

```python
def cmd_jobs(target_str, config):
    """List all runs, optionally filtered by target project."""
    runs_dir = Path.home() / ".claude-devkit" / "runs"
    if not runs_dir.is_dir():
        print("No runs found.")
        return 0

    runs = []
    for run_dir in sorted(runs_dir.iterdir(), reverse=True):
        meta_path = run_dir / "meta.json"
        if not meta_path.exists():
            continue
        meta = json.loads(meta_path.read_text())

        # Check liveness for "running" status
        if meta.get("status") == "running":
            pid = meta.get("pid")
            if pid and not _is_pid_alive(pid):
                meta["status"] = "stale"

        if target_str:
            ok, resolved = validate_target(target_str, config)
            if ok and meta.get("target") != str(resolved):
                continue

        runs.append(meta)

    if not runs:
        print("No runs found.")
        return 0

    print(f"{'RUN ID':<28} {'SKILL':<12} {'PROJECT':<20} {'STATUS':<10} {'STARTED'}")
    for meta in runs[:20]:
        print(
            f"{meta['run_id']:<28} "
            f"{meta.get('skill','?'):<12} "
            f"{meta.get('project_name','?'):<20} "
            f"{_status_color(meta.get('status','?')):<10} "
            f"{meta.get('started_at','?')}"
        )
    return 0
```

### Change 6: `devkit result <run-id>` and `devkit logs <run-id>`

```python
def cmd_result(run_id, config):
    """Print the result of a completed run."""
    ok, err = _validate_run_id(run_id)
    if not ok:
        print(err)
        return 1
    run_dir = Path.home() / ".claude-devkit" / "runs" / run_id
    result_path = run_dir / "result.json"
    if result_path.exists():
        data = json.loads(result_path.read_text())
        print(data.get("result", "(no result text)"))
    elif (run_dir / "stdout.log").exists():
        print((run_dir / "stdout.log").read_text())
    else:
        print(f"No result found for run {run_id}")
        return 1
    return 0

def cmd_logs(run_id, config):
    """Print stderr logs of a run."""
    ok, err = _validate_run_id(run_id)
    if not ok:
        print(err)
        return 1
    log_path = Path.home() / ".claude-devkit" / "runs" / run_id / "stderr.log"
    if not log_path.exists():
        print(f"No logs found for run {run_id}")
        return 1
    print(log_path.read_text())
    return 0
```

### Change 7: Run Cleanup

`cmd_clean` checks PID liveness for runs still marked "running" (handles the case where the watcher died before updating status). Retention days are read from `devkit-defaults.json` with a hardcoded fallback.

```python
def cmd_clean(max_age_days, config):
    """Remove completed/failed runs older than max_age_days."""
    if max_age_days is None:
        max_age_days = config.get("clean_retention_days", 7)
    runs_dir = Path.home() / ".claude-devkit" / "runs"
    if not runs_dir.is_dir():
        return 0
    cutoff = time.time() - (max_age_days * 86400)
    removed = 0
    for run_dir in runs_dir.iterdir():
        ok, _ = _validate_run_id(run_dir.name)
        if not ok:
            continue
        meta_path = run_dir / "meta.json"
        if not meta_path.exists():
            shutil.rmtree(run_dir, ignore_errors=True)
            removed += 1
            continue
        meta = json.loads(meta_path.read_text())
        status = meta.get("status")
        # Check PID liveness for runs still marked "running"
        # (handles case where watcher died before finalizing)
        if status == "running":
            pid = meta.get("pid")
            if pid and not _is_pid_alive(pid):
                status = "stale"
        if status in ("completed", "failed", "stale"):
            mtime = meta_path.stat().st_mtime
            if mtime < cutoff:
                shutil.rmtree(run_dir, ignore_errors=True)
                removed += 1
    print(f"Cleaned {removed} run(s)")
    return 0
```

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Orphaned watcher processes if parent is killed between Popen calls | Low | Low | Watcher is stateless -- if it dies before spawning Claude, `status` stays `running` with `pid: None`; `devkit jobs` detects stale PIDs. |
| Disk space from accumulated run logs | Medium | Low | `devkit clean` with configurable retention (default 7 days). Run directories are small (a few KB each). |
| Race condition in meta.json writes (watcher vs user reading) | Low | Low | Atomic writes via tempfile + `os.rename()`. Reader sees either pre- or post-completion state, never partial. |
| Multiple concurrent detached runs on same project | Low | Low | Each run has its own run ID and directory. No shared state conflicts. Skills may conflict (e.g., two `/ship` runs), but that's a user responsibility, same as today. |

## Security Requirements

### Assets at Risk

| Asset | Classification | Notes |
|-------|---------------|-------|
| Run output (stdout.log, result.json) | Internal | May contain code snippets, plan text, review findings. Not secrets, but potentially sensitive IP. |
| Run metadata (meta.json) | Internal | Contains project paths, skill names, timestamps. Not secret but reveals work patterns. |
| PID files | Internal | Process IDs -- low sensitivity. |
| `~/.claude-devkit/runs/` directory | Internal | Contains all of the above. |

### Trust Boundaries

| Boundary | Inside (Trusted) | Outside (Untrusted) |
|----------|------------------|---------------------|
| TB-1: User session | devkit process, watcher, file writes | Other local users on shared machine |
| TB-2: Process boundary | devkit parent process | Claude subprocess (semi-trusted -- produces output consumed by result parsing) |
| TB-3: File system | `~/.claude-devkit/runs/` (permissions 0o700) | `/tmp`, project directories (potentially writable by other processes) |
| TB-4: Inline code execution | devkit_cli.py (reviewed source code) | Watcher script (runtime-generated code string passed via `sys.executable -c`, not subject to normal code review) |

TB-4 is mitigated by: (a) the watcher script is a static string literal with no interpolation -- all variable values arrive via `sys.argv`, (b) the only consumer of `sys.argv` values is `Path()` and `json.loads()`, not `eval()` or `exec()`.

### STRIDE Analysis

#### Spoofing -- Run ID Collision

| Threat | Risk | Mitigation |
|--------|------|------------|
| Attacker crafts a run ID to overwrite an existing run's output | Very Low | Run IDs include 6 random chars (36^6 = ~2 billion combinations) plus timestamp. `os.makedirs()` fails if directory exists. No user-supplied run IDs accepted by `--detach` (generated internally only). |

#### Tampering -- Run Output Manipulation

| Threat | Risk | Mitigation |
|--------|------|------------|
| Attacker modifies stdout.log/result.json between write and user retrieval | Low | Run directories created with `os.makedirs(mode=0o700)`. Log files created with `os.open(..., 0o600)`. No network exposure. Local-only threat model -- if an attacker has write access to `~/.claude-devkit/`, they already have the user's shell. |

#### Repudiation -- Run Lifecycle Events

| Threat | Risk | Mitigation |
|--------|------|------------|
| No audit trail for detached run initiation or completion | Low | `meta.json` records `started_at` and `completed_at` timestamps, skill name, target, and exit code. Deletion of `meta.json` (by user or `devkit clean`) removes the record. For the local CLI threat model, this is acceptable -- the user is the only actor. If future use cases require tamper-evident logging, run lifecycle events can be emitted to the existing `emit-audit-event.sh` infrastructure. |
| Modified result.json not detectable post-hoc | Low | Accepted risk for MVP. `result.json` is derived from `stdout.log` -- users can cross-check. Integrity checksums are a future enhancement if needed. |

#### Information Disclosure -- Run Output Leakage

| Threat | Risk | Mitigation |
|--------|------|------------|
| Run output readable by other users on shared machine | Low | Directory created with `os.makedirs(mode=0o700)`. Files created with `os.open(..., 0o600)`. Standard Unix permission model. |
| Run output persists after user expects it deleted | Low | `devkit clean` with configurable retention. Users can `rm -rf ~/.claude-devkit/runs/<id>` manually. |

#### Denial of Service -- Resource Exhaustion

| Threat | Risk | Mitigation |
|--------|------|------------|
| Many concurrent `--detach` calls exhaust system resources | Low | No concurrency limit enforced -- user responsibility, same as running multiple `claude` sessions manually. Each run is one `claude` process + one lightweight watcher. OS process limits are the backstop. |
| Accumulated run directories fill disk | Medium | `devkit clean` with configurable retention (default 7 days via `clean_retention_days`). Run directories are small (~10-50 KB each). Could add a max-runs config in a future phase. |

#### Elevation of Privilege -- Process Injection

| Threat | Risk | Mitigation |
|--------|------|------------|
| Watcher script injection via crafted values | Very Low | The watcher script is a static string literal. All variable values (`runs_dir`, `invocation`, `cwd`) are passed via `sys.argv`, not interpolated into source code. No f-string embedding of paths or user data. |
| Malicious run ID passed to `devkit result`/`devkit logs` | Low | `_validate_run_id()` checks `Path(run_id).name == run_id`, rejecting path traversal. Called at the top of `cmd_result()`, `cmd_logs()`, and `cmd_clean()`. |

### Security Controls

1. **File permissions:** Run directories created with `os.makedirs(mode=0o700)`. Files created with `os.open(path, flags, 0o600)`. `meta.json` gets `os.chmod(0o600)` after `_atomic_write_json()` in the parent.
   - **Failure mode:** If permission setting fails (e.g., network filesystem, ACL override), run output may be world-readable. Log a warning to stderr if `os.chmod()` raises `OSError`.
2. **No user-supplied paths in watcher:** Watcher script is a static string literal; all variable values arrive via `sys.argv`.
   - **Failure mode:** If a future change embeds user input via f-string, it becomes a code injection vector. Mitigated by: the pattern of using `sys.argv` is documented and testable; a grep-based CI check for f-string interpolation in watcher code would catch regressions.
3. **Run ID validation:** `_validate_run_id()` centralized helper called by `cmd_result()`, `cmd_logs()`, and `cmd_clean()`.
   - **Failure mode:** If a new command accepts run IDs without calling `_validate_run_id()`, path traversal is possible. Mitigated by: centralized function makes the pattern obvious; test `test_run_id_no_path_traversal` catches missing validation.
4. **No shell=True:** All subprocess calls use list form.
   - **Failure mode:** If a future developer uses `shell=True`, command injection becomes possible. Mitigated by: test `test_detach_no_shell_true` greps source for violations.
5. **Atomic writes:** Parent uses `_atomic_write_json()`. Watcher uses inline atomic write (`os.open` with 0o600 + `os.rename`).
   - **Failure mode:** If atomic write fails (disk full, permission error on temp file), meta.json may be left in an inconsistent state. Watcher wraps the final write in try/except; if it fails, meta.json retains the "running" state, which `devkit jobs` will mark as "stale" once the PID dies.
